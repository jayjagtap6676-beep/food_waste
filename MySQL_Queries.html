How to use this page

  1. Open MySQL Workbench, connect, and run USE food_waste_db; first.
  2. Click inside a query and press Ctrl + Enter to run just that statement. To run several lines you selected, use Ctrl + Shift + Enter.
  3. Every query was written for the final database (11 tables, 7 views, 9 triggers). The Expect lines assume a database that has just been loaded from food_waste_full.sql. After the website demo the numbers will differ, so reload the SQL if you want the exact figures.

read only safe, changes nothing. MySQL only uses MySQL features such as SHOW or NOW(); read only. changes data inserts, updates or deliberately fails; run in the order shown on a fresh load.

Safe Updates: the UPDATE and DELETE statements here all use a key column in the WHERE clause, so Workbench's Safe Updates mode does not block them. Only the expiry clean-up in the SQL file needs that mode switched off.
Not yet run on a real MySQL server. The read-only queries were checked for correct table and column names and for the expected results against a stand-in copy of the data; the MySQL-only statements and the trigger tests were checked by reading. Comparison and logical operatorsread only

AND, OR, NOT together with >= and =.

  AND (listing_status = 'Available' OR listing_status = 'Allocated')

3. Joins

Lab Exp 4: inner, left, right, cross and self joins across the tables of the ER diagram.

Inner join of three tablesread only

Each listing with its donor and category (relationships LISTS and CLASSIFIES).

SELECT l.listing_id, l.food_name, d.donor_name, c.category_name, c.storage_type
FROM Food_Listing l
JOIN Donor d ON d.donor_id = l.donor_id
JOIN Food_Category c ON c.category_id = l.category_id
ORDER BY l.listing_id;
Expect: 5 rows.

Four-table join: who requested what from whomread only

The many-to-many link between NGOs and listings, resolved by Collection_Request.

SELECT r.request_id, n.ngo_name, l.food_name, d.donor_name, r.quantity_kg, r.request_status
FROM Collection_Request r
JOIN NGO n ON n.ngo_id = r.ngo_id
JOIN Food_Listing l ON l.listing_id = r.listing_id
JOIN Donor d ON d.donor_id = l.donor_id
ORDER BY r.request_id;
Expect: Fresh load: Completed, Completed, Approved, Pending, Rejected.

Six-table join: the whole delivery chainread only

Donor to NGO, carried by which volunteer.

SELECT dl.delivery_id, d.donor_name AS from_donor, n.ngo_name AS to_ngo,
       v.volunteer_name, dl.delivery_status
FROM Delivery dl
JOIN Collection_Request r ON r.request_id = dl.request_id
JOIN Food_Listing l ON l.listing_id = r.listing_id
JOIN Donor d ON d.donor_id = l.donor_id
JOIN NGO n ON n.ngo_id = r.ngo_id
JOIN Volunteer v ON v.volunteer_id = dl.volunteer_id;

LEFT JOIN: every NGO, even with no requestsread only

Asha Children Home appears with 0 requests.

SELECT n.ngo_name, n.verified_status, COUNT(r.request_id) AS requests_made
FROM NGO n
LEFT JOIN Collection_Request r ON r.ngo_id = n.ngo_id
GROUP BY n.ngo_id, n.ngo_name, n.verified_status;
Expect: Fresh load: Annadaan 3, Roti Bank 2, Asha 0.

LEFT JOIN with IS NULL: listings nobody requestedread only

Rows with no match on the right side.

SELECT l.listing_id, l.food_name
FROM Food_Listing l
LEFT JOIN Collection_Request r ON r.listing_id = l.listing_id
WHERE r.request_id IS NULL;
Expect: Fresh load: Fresh Vegetables.

RIGHT JOIN: every volunteer with their deliveriesread only

Volunteers without a delivery would still appear.

SELECT v.volunteer_name, dl.delivery_id, dl.delivery_status
FROM Delivery dl
RIGHT JOIN Volunteer v ON v.volunteer_id = dl.volunteer_id;

Weak entity joined to its ownerread only

Quality_Check rows only exist together with their delivery.

SELECT dl.delivery_id, q.check_no, q.check_stage, q.temperature_c, q.result
FROM Delivery dl
JOIN Quality_Check q ON q.delivery_id = dl.delivery_id
ORDER BY dl.delivery_id, q.check_no;

CROSS JOIN: possible assignmentsread only

Every approved request that has no delivery yet, paired with every free volunteer.

SELECT r.request_id, v.volunteer_name
FROM Collection_Request r
CROSS JOIN Volunteer v
WHERE r.request_status = 'Approved' AND v.availability = 'Available'
  AND NOT EXISTS (SELECT 1 FROM Delivery dl WHERE dl.request_id = r.request_id);
Expect: Fresh load: no rows (the only approved request already has a delivery). It fills after you approve a request in the demo.

Self join: two donors in the same cityread only

A table joined to itself.

SELECT a.donor_name AS donor_1, b.donor_name AS donor_2, a.city
FROM Donor a
JOIN Donor b ON a.city = b.city AND a.donor_id < b.donor_id;

4. Aggregates, GROUP BY and HAVING

Lab Exp 4: COUNT, SUM, AVG, MIN, MAX with grouping.

Aggregate functions over a tableread only

Summary of the remaining stock.

SELECT COUNT(*) AS listings, SUM(quantity_kg) AS total_kg, AVG(quantity_kg) AS avg_kg,
       MIN(quantity_kg) AS smallest, MAX(quantity_kg) AS largest
FROM Food_Listing;
Expect: Fresh load: 5, 175.00, 35.000, 10.00, 80.00.

GROUP BY: stock per categoryread only

COALESCE turns the NULL of an empty category into 0.

SELECT c.category_name, COUNT(l.listing_id) AS listings,
       COALESCE(SUM(l.quantity_kg), 0) AS stock_kg
FROM Food_Category c
LEFT JOIN Food_Listing l ON l.category_id = c.category_id
GROUP BY c.category_id, c.category_name
ORDER BY stock_kg DESC;
Expect: Frozen Foods shows 0.

GROUP BY: requests by statusread only

How the requests are spread over the life cycle.

SELECT request_status, COUNT(*) AS requests, SUM(quantity_kg) AS kg
FROM Collection_Request
GROUP BY request_status;
Expect: Fresh load: Approved 1, Completed 2, Pending 1, Rejected 1.

GROUP BY: kilograms requested per NGOread only

SELECT n.ngo_name, COUNT(r.request_id) AS requests, COALESCE(SUM(r.quantity_kg), 0) AS kg_requested
FROM NGO n
LEFT JOIN Collection_Request r ON r.ngo_id = n.ngo_id
GROUP BY n.ngo_id, n.ngo_name
ORDER BY kg_requested DESC;

HAVING: donors with at least 2 listingsread only

HAVING filters groups; WHERE filters rows.

SELECT d.donor_name, COUNT(l.listing_id) AS listings, SUM(l.quantity_kg) AS stock_kg
FROM Donor d
JOIN Food_Listing l ON l.donor_id = d.donor_id
GROUP BY d.donor_id, d.donor_name
HAVING COUNT(l.listing_id) >= 2;
Expect: Fresh load: Sai Bakery (40 kg) and FreshMart (120 kg).

HAVING: NGOs that received more than 20 kgread only

Only completed deliveries count.

SELECT n.ngo_name, SUM(dl.delivered_kg) AS kg_received
FROM NGO n
JOIN Collection_Request r ON r.ngo_id = n.ngo_id
JOIN Delivery dl ON dl.request_id = r.request_id
WHERE dl.delivery_status = 'Delivered'
GROUP BY n.ngo_id, n.ngo_name
HAVING SUM(dl.delivered_kg) > 20;
Expect: Fresh load: Roti Bank Mumbai, 25.00.

Volunteer performanceread only

SELECT v.volunteer_name, COUNT(dl.delivery_id) AS deliveries, COALESCE(SUM(dl.delivered_kg), 0) AS kg_delivered
FROM Volunteer v
LEFT JOIN Delivery dl ON dl.volunteer_id = v.volunteer_id
GROUP BY v.volunteer_id, v.volunteer_name;

Quality pass rate per storage typeread only

A true comparison counts as 1, so SUM counts the matches.

SELECT c.storage_type, COUNT(*) AS checks, SUM(q.result = 'Pass') AS passed,
       ROUND(100 * SUM(q.result = 'Pass') / COUNT(*), 1) AS pass_percent
FROM Quality_Check q
JOIN Delivery dl ON dl.delivery_id = q.delivery_id
JOIN Collection_Request r ON r.request_id = dl.request_id
JOIN Food_Listing l ON l.listing_id = r.listing_id
JOIN Food_Category c ON c.category_id = l.category_id
GROUP BY c.storage_type;
Expect: Fresh load: Hot and Room, both 100.0.

5. Nested queries (subqueries)

Lab Exp 4 and 8: subqueries with IN, EXISTS, ALL, scalar and derived tables.

Three-level nested IN: NGOs that requested from FreshMartread only

Subquery inside subquery inside subquery.

SELECT ngo_name FROM NGO
WHERE ngo_id IN (SELECT ngo_id FROM Collection_Request
                 WHERE listing_id IN (SELECT listing_id FROM Food_Listing
                                      WHERE donor_id = (SELECT donor_id FROM Donor WHERE donor_name = 'FreshMart')));
Expect: Annadaan Foundation and Roti Bank Mumbai.

Scalar subquery: above-average stockread only

The inner query returns a single value.

SELECT food_name, quantity_kg
FROM Food_Listing
WHERE quantity_kg > (SELECT AVG(quantity_kg) FROM Food_Listing);
Expect: Fresh load: Packed Milk and Curd, Fresh Vegetables.

NOT EXISTS (correlated): NGOs with no completed requestread only

The inner query refers to the outer row.

SELECT n.ngo_name FROM NGO n
WHERE NOT EXISTS (SELECT 1 FROM Collection_Request r
                  WHERE r.ngo_id = n.ngo_id AND r.request_status = 'Completed');
Expect: Fresh load: Asha Children Home.

EXISTS: volunteers who have deliveredread only

SELECT volunteer_name FROM Volunteer v
WHERE EXISTS (SELECT 1 FROM Delivery dl
              WHERE dl.volunteer_id = v.volunteer_id AND dl.delivery_status = 'Delivered');

NOT IN: donors who never posted foodread only

SELECT donor_name FROM Donor
WHERE donor_id NOT IN (SELECT donor_id FROM Food_Listing);
Expect: Fresh load: Green Kitchen.

Subquery in the SELECT listread only

Stock left next to the kilograms already allocated.

SELECT l.food_name, l.quantity_kg AS stock_left,
       (SELECT COALESCE(SUM(r.quantity_kg), 0) FROM Collection_Request r
        WHERE r.listing_id = l.listing_id AND r.request_status IN ('Approved','Completed')) AS kg_allocated
FROM Food_Listing l;

Derived table (subquery in FROM)read only

Average of per-NGO totals.

SELECT AVG(total_kg) AS avg_kg_per_ngo
FROM (SELECT ngo_id, SUM(quantity_kg) AS total_kg
      FROM Collection_Request
      GROUP BY ngo_id) AS per_ngo;

ALL: bigger than every bakery listingMySQL only

Bakery Items is category 2.

SELECT food_name, quantity_kg
FROM Food_Listing
WHERE quantity_kg > ALL (SELECT quantity_kg FROM Food_Listing WHERE category_id = 2);
Expect: Fresh load: Packed Milk and Curd, Fresh Vegetables.

Questions the system exists to answer.

Food that must be collected in the next 6 hoursMySQL only

Perishability: what to move first.

SELECT food_name, donor_name, quantity_kg, expiry_on
FROM v_available_listings
WHERE expiry_on <= DATE_ADD(NOW(), INTERVAL 6 HOUR)

Stock reconciliation: no kilogram lostread only

Remaining plus allocated gives back the original quantity, which proves the stock triggers are consistent.

SELECT l.listing_id, l.food_name, l.quantity_kg AS remaining,
       COALESCE(SUM(r.quantity_kg), 0) AS allocated,
       l.quantity_kg + COALESCE(SUM(r.quantity_kg), 0) AS original_total
FROM Food_Listing l
LEFT JOIN Collection_Request r ON r.listing_id = l.listing_id AND r.request_status IN ('Approved','Completed')
GROUP BY l.listing_id, l.food_name, l.quantity_kg;

NGO capacity used in the last 24 hoursMySQL only

The numbers behind the capacity rule in trg_request_bu.

LEFT JOIN Collection_Request r ON r.ngo_id = n.ngo_id
     AND r.request_status IN ('Approved','Completed')

10. Prove the constraints

These statements are meant to fail. Run them one at a time.

CHECK constraintchanges data

The allowed values are Available, Busy and Offline.

UPDATE Volunteer SET availability = 'Sleeping' WHERE volunteer_id = 1;
Expect: ERROR 3819: Check constraint ... is violated.

CHECK on a numberchanges data

Quantities must be above zero.

INSERT INTO Collection_Request (listing_id, ngo_id, quantity_kg) VALUES (3, 1, -5);
Expect: ERROR 3819.

FOREIGN KEYchanges data

Donor 99 does not exist.

INSERT INTO Donor_Phone (donor_id, phone) VALUES (99, '9999999999');
Expect: ERROR 1452: a foreign key constraint fails.

UNIQUEchanges data

Usernames must be unique.

INSERT INTO User_Account (username, password, role) VALUES ('admin', 'whatever1', 'Admin');
Expect: ERROR 1062: Duplicate entry.

NOT NULLchanges data

The phone number is required.

INSERT INTO NGO_Phone (ngo_id) VALUES (1);
Expect: ERROR 1364: Field 'phone' doesn't have a default value.

ON DELETE CASCADEchanges data

A safe delete that is undone.

SELECT COUNT(*) AS phones_of_donor_1 FROM Donor_Phone WHERE donor_id = 1;
START TRANSACTION;
DELETE FROM Donor_Phone WHERE donor_id = 1;
SELECT COUNT(*) AS phones_inside FROM Donor_Phone WHERE donor_id = 1;
ROLLBACK;
SELECT COUNT(*) AS phones_after_rollback FROM Donor_Phone WHERE donor_id = 1;
Expect: 2, then 0 inside the transaction, then 2 again.

11. Transactions (COMMIT, ROLLBACK, SAVEPOINT)

Lab Exp 10. All of these are safe to run.

COMMIT saves the workchanges data

The change stays.

START TRANSACTION;
UPDATE NGO SET daily_capacity_kg = daily_capacity_kg + 10 WHERE ngo_id = 1;
COMMIT;
SELECT ngo_name, daily_capacity_kg FROM NGO WHERE ngo_id = 1;
Expect: Annadaan: 210.

ROLLBACK undoes the workchanges data

The first SELECT shows 5, the second shows the old value.

START TRANSACTION;
UPDATE NGO SET daily_capacity_kg = 5 WHERE ngo_id = 1;
SELECT ngo_name, daily_capacity_kg FROM NGO WHERE ngo_id = 1;
ROLLBACK;
SELECT ngo_name, daily_capacity_kg FROM NGO WHERE ngo_id = 1;

SAVEPOINT: undo only partchanges data

The vehicle change is undone, the capacity change is kept.

START TRANSACTION;
UPDATE NGO SET daily_capacity_kg = daily_capacity_kg + 50 WHERE ngo_id = 2;
SAVEPOINT after_ngo;
UPDATE Volunteer SET vehicle_type = 'Van' WHERE volunteer_id = 1;
ROLLBACK TO SAVEPOINT after_ngo;
SELECT vehicle_type FROM Volunteer WHERE volunteer_id = 1;
COMMIT;
SELECT daily_capacity_kg FROM NGO WHERE ngo_id = 2;
Expect: Rohan keeps Bike; Roti Bank gains 50.

ROLLBACK also undoes what the triggers didchanges data

Approval deducts stock inside the transaction; ROLLBACK returns it. Needs request 4 to be Pending.

SELECT listing_id, quantity_kg FROM Food_Listing WHERE listing_id = 3;
START TRANSACTION;
UPDATE Collection_Request SET request_status = 'Approved' WHERE request_id = 4;
SELECT listing_id, quantity_kg FROM Food_Listing WHERE listing_id = 3;
ROLLBACK;
SELECT listing_id, quantity_kg FROM Food_Listing WHERE listing_id = 3;
SELECT request_id, request_status FROM Collection_Request WHERE request_id = 4;
Expect: 40, 15, 40, and the request is Pending again.

12. DDL and DML demos (Exp 1 and 2)

Only if the instructor asks for CREATE, ALTER, TRUNCATE, DROP, INSERT, UPDATE and DELETE. Everything is done on a copy or on a new row.

Create from a query, add a key, add and change a column, add a constraint, empty the table, remove it.
