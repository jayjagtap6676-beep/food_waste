Run the website on your laptop

Food Waste Recovery & Redistribution · MySQL database + Flask website. Follow the parts in order. The website reads and writes the MySQL database you load in part 3.

1. What is inside the zip

food_waste_project/ README_STEPS.html this page run_website.bat double-click to install the packages and start the website (Windows) sql/ food_waste_full.sql the whole database: 11 tables, 7 views, 9 triggers, data app/ app.py auth.py db.py listings.py delivery.py the website (Python Flask) config_local.py your MySQL password goes here requirements.txt templates/ 12 HTML pages
How the two parts connect: the SQL file only builds the database food_waste_db inside your MySQL server. The website (app/db.py) then logs in to that server with root and your password and sends it ordinary SQL. The rules (triggers) and the views live inside MySQL, so the website never has to repeat them.

2. Install (once)

  1. MySQL Server 8.0.16 or newer and MySQL Workbench (MySQL Installer from mysql.com, Custom or Full). Remember the root password you set. Keep port 3306.
  2. Python 3.10 or newer from python.org. In the installer tick Add python.exe to PATH.
  3. Check the versions: in Workbench run SELECT VERSION(); (must be 8.0.16 or higher, otherwise CHECK constraints are ignored). In Command Prompt run python --version.

3. Load the database into MySQL

  1. Open MySQL Workbench and click your local connection (usually Local instance MySQL80). Enter the root password.
  2. File > Open SQL Script and choose sql/food_waste_full.sql from the unzipped folder.
  3. Click the lightning icon (runs the whole script). It deletes and rebuilds food_waste_db, so you can repeat it any time to reset the data.
  4. Check it worked: run
USE food_waste_db;
SHOW FULL TABLES;      -- 11 tables and 7 views
SHOW TRIGGERS;         -- 9 triggers
SELECT username, role FROM User_Account;
Run it as one script. Triggers contain semicolons, so running them line by line fails. The last section of the script contains transaction blocks that COMMIT, so the database after loading is not the bare sample data: request 3 is already approved and given to Rohan, delivery 2 is delivered, and a donor called Green Kitchen exists.

4. Connect the website to your MySQL

  1. Open app/config_local.py in Notepad and put your real root password between the quotes:
DB_PASSWORD = "your_mysql_password"
  1. That is the only required change. The connection details the website uses are in app/db.py:
DB_CONFIG = {"host": "localhost", "user": "root", "password": DB_PASSWORD, "database": "food_waste_db"}

If your MySQL user is not root, or MySQL runs on another port, change this line (add "port": 3307 for example). The database name must stay food_waste_db, which is what the SQL file creates.

5. Start the website

Easy way (Windows): double-click run_website.bat. Manual way: open the app folder, type cmd in the address bar and press Enter, then run:

pip install -r requirements.txt
python app.py

Open http://localhost:5000 in the browser. Keep the black window open while you use the site; stop it with Ctrl + C.

7. What changed compared with your three guides

The 12 pages in templates, auth.py, config_local.py and requirements.txt are exactly the files from the guides. The SQL no longer has stored procedures, custom error messages or some views the guides assumed, so these parts had to change:

FileChange
app/db.pycall_proc removed. New run_in_transaction (START TRANSACTION, COMMIT, ROLLBACK on any error) and expire_listings (the clean-up of SQL section 5).
app/app.pyLogin is one SELECT instead of sp_login (wrong password and blocked account are checked in Python). Registration already used a transaction and is unchanged.
app/listings.pyApprove, cancel listing and expiry no longer call procedures. Because triggers now store a bad request as Rejected instead of raising an error, the page checks the saved status and shows a message. Posting a listing reports if the expiry was shortened or the food was already expired.
app/delivery.pyAssigning is a plain INSERT (the trigger refuses an invalid one). Status changes are done in Python: pickup and delivery times are set, the order Assigned > Picked Up > Delivered is enforced and a passing quality check is required (the SQL file does not enforce that order itself).
sql/food_waste_full.sqlViews changed to the column names the pages use, plus v_ngo_summary, v_volunteer_summary and v_quality_by_category (renamed from v_quality_summary). Password minimum length 4 (the register page allows 4). Truck added to the vehicle list (the register page offers it).
Not tested against a real MySQL server or a real browser session: the website code was checked with a stand-in database, and the SQL has never been run on MySQL. The first real run is your first real test. If anything fails, copy the exact message and the line it points to.

8. Problems and fixes

MessageMeaning / fix
Access denied for user 'root'Wrong password in app/config_local.py.
Unknown database 'food_waste_db'The SQL file has not been run yet (part 3).
Can't connect to MySQL server on 'localhost'MySQL is not running (start it from Windows Services) or uses another port (see part 4).
No module named flask / mysqlRun pip install -r requirements.txt inside the app folder.
'python' is not recognizedReinstall Python and tick Add python.exe to PATH.
Table or view 'v_...' doesn't existLoad the SQL again; the script stopped before the views. Run it as one script.
Error 1175 (safe update mode)Workbench blocks the expiry clean-up. Untick Safe Updates in Edit > Preferences > SQL Editor, reconnect, run the script again.
You have an error in your SQL syntax near '$$'The triggers were run line by line. Run the whole file with the lightning icon.
Check constraint ... is violated (shown on a page)A value broke a rule, for example a 4-digit pincode or a 9-digit phone number.
Demo shows Rejected where Approved was expectedThe sample times are relative to when the SQL was loaded, so very old data expires. Run the SQL again.
